Тема 6.4: Застосування блокчейну в кібербезпеці

Незмінний журнал подій (Audit Log)

  • Проблема: атакуючі видаляють або модифікують логи після атаки — інцидент стає непомітним
  • MITRE ATT&CK T1070: видалення індикаторів (Indicator Removal on Host) — стандартна техніка APT-атак
  • Рішення: хеші логів записуються в блокчейн у реальному часі — незмінний audit trail
  • Навіть при повній компрометації системи хеші в розподіленому реєстрі залишаються незмінними
  • Timestamping (часові мітки): криптографічний доказ часу події — критично для forensic-розслідувань
  • Юридична значущість: незмінний запис прийнятний як доказ у судових процесах

Варіанти реалізації Audit Log

PKI (інфраструктура відкритих ключів) та Certificate Transparency

  • Проблема: централізовані CA (Certificate Authority) — єдина точка відмови (single point of failure)
  • DigiNotar (2011): голландський CA зламано — випущено фейкові сертифікати Google, постраждали 300K+ іранських користувачів
  • Symantec (2017): найбільший CA визнано ненадійним — Chrome та Firefox видалили всі його сертифікати
  • Blockchain PKI: децентралізована видача сертифікатів — немає єдиного органу для компрометації
  • Автоматичне Certificate Transparency: кожна видача публічно видна — фейковий сертифікат виявляється миттєво
  • Миттєве відкликання (Revocation): оновлення через смарт-контракт за секунди замість днів (CRL/OCSP)

Атака на ланцюг постачання: SolarWinds (2020)

in-toto + Blockchain: захист ланцюга постачання

  • in-toto (NYU): фреймворк end-to-end верифікації software supply chain (ланцюга постачання ПЗ)
  • Кожен крок CI/CD (code review, build, test, sign, deploy) підписується відповідальною стороною
  • Хеші всіх артефактів та attestations (підтверджень) зберігаються в блокчейні
  • Кінцевий користувач верифікує весь ланцюг — від git commit до release binary
  • SLSA (Supply-chain Levels for Software Artifacts): фреймворк Google, сумісний з blockchain attestation
  • Codecov (2021): скомпрометований bash uploader збирав secrets — блокчейн-верифікація запобігла б атаці

Обмін розвідкою загроз (Threat Intelligence Sharing)

  • Проблема: компанії не діляться IoC через конкуренцію, юридичні ризики та репутаційні побоювання
  • Рішення: анонімний або псевдонімний обмін через блокчейн — джерело не розкривається
  • Token incentives (токенні стимули): учасники отримують токени за якісну та своєчасну інформацію
  • Reputation system (система репутації): on-chain репутація джерел — IoC від перевіреного джерела має більшу вагу
  • PolySwarm: marketplace для threat detection — антивірусні вендори конкурують за токени
  • MISP + Blockchain: децентралізований MISP з блокчейн-розширенням для незмінності та довіри

Безпека IoT (Інтернету речей): масштаб проблеми

75+ мільярдів

IoT-пристроїв очікується до 2030 року

Mirai Botnet (2016)

600K+ пристроїв, DDoS на Dyn DNS — впали Twitter, Netflix, GitHub

Слабка автентифікація

Дефолтні паролі, hardcoded credentials, відсутність шифрування

Blockchain-рішення

DID для пристроїв, смарт-контракти для access control

Блокчейн для IoT-безпеки

  • Device Identity (ідентичність пристрою): DID для кожного IoT-пристрою — децентралізована ідентичність, незалежна від виробника
  • Access Control (контроль доступу): смарт-контракти автоматично управляють правами доступу між пристроями
  • Firmware Updates (оновлення прошивки): хеш автентичного firmware у блокчейні — пристрій перевіряє перед встановленням
  • IOTA (Tangle): DAG-based протокол для IoT — feeless мікротранзакції, lightweight для обмежених ресурсів
  • Helium: децентралізована IoT-мережа з PoC (Proof of Coverage) консенсусом — 900K+ hotspots
  • Гетерогенність: тисячі виробників, різні протоколи — блокчейн як єдиний шар довіри

Обмеження блокчейну в безпеці

  • Масштабованість (Scalability): публічні блокчейни обробляють на порядки менше TPS ніж традиційні СУБД
  • Приватність (Privacy): прозорість публічних блокчейнів суперечить вимогам GDPR та захисту даних
  • Незмінність (Immutability): помилкові дані не виправити, «право на забуття» неможливе
  • Атака 51%: контроль більшості потужності дозволяє маніпулювати ланцюгом (Ethereum Classic, Bitcoin Gold)
  • Складність інтеграції (Complexity): перебудова бізнес-процесів значно підвищує вартість впровадження
  • Енергоспоживання: PoW-блокчейни створюють екологічні проблеми (перехід на PoS пом'якшує)

Коли використовувати блокчейн?

Реальні кейси застосування

Постквантова криптографія (Post-Quantum Cryptography)

  • Загроза: алгоритм Шора на квантовому комп'ютері здатен зламати ECDSA, RSA та інші поточні алгоритми
  • NIST PQC (2024): завершено стандартизацію перших постквантових алгоритмів
  • CRYSTALS-Kyber: стандарт для шифрування (key encapsulation), базується на теорії ґраток (lattice-based)
  • CRYSTALS-Dilithium: стандарт для цифрових підписів — замінить ECDSA у блокчейнах
  • Ethereum Foundation: активно досліджує міграцію на PQC — складність через мільйони існуючих акаунтів
  • Harvest Now, Decrypt Later: зловмисники вже збирають зашифровані дані для майбутнього дешифрування

NIST PQC: хронологія стандартизації

Layer 2 Rollups: масштабування блокчейну

Міжланцюгова взаємодія (Interoperability) та Enterprise

  • Cross-chain bridges (мости): передача активів між блокчейнами — найвразливіший компонент екосистеми
  • 2022: через хаки мостів втрачено понад $2 мільярди (Ronin Bridge, Wormhole, Nomad)
  • Протоколи: Cosmos IBC, Polkadot XCM, LayerZero — стандартизована міжланцюгова комунікація
  • Hyperledger (Linux Foundation): Fabric для бізнес-процесів, Besu для Ethereum-сумісності, Iroha для IoT
  • R3 Corda: спеціалізація на фінансовому секторі — десятки банків та страхових компаній
  • BaaS (Blockchain-as-a-Service): Amazon Managed Blockchain, Azure Blockchain Service, IBM Blockchain Platform
