Тема 6.3: Смарт-контракти та їх безпека

Що таке смарт-контракт (Smart Contract)?

  • Програма, розгорнута на блокчейні, що автоматично виконує умови угоди
  • Code is Law (код — це закон): автоматичне та невідворотне виконання
  • Незмінність (Immutability): після розгортання (deploy) код не можна модифікувати
  • Прозорість (Transparency): вихідний код публічно доступний для аудиту
  • Безпосередність (Trustless Execution): не потрібен посередник, код виконується валідаторами
  • Термін запропонований Ніком Сабо у 1994 році, задовго до появи блокчейну

Платформи смарт-контрактів (Smart Contract Platforms)

Атака повторного входу (Reentrancy Attack)

  • Зловмисний контракт повторно викликає функцію жертви до завершення попереднього виконання
  • Стан (balance) не оновлений на момент повторного виклику — кошти знімаються повторно
  • Fallback-функція атакуючого автоматично ініціює повторний виклик withdraw()
  • Цикл повторюється, поки не вичерпається газ (gas) або баланс контракту
  • Захист: патерн Checks-Effects-Interactions (CEI) та модифікатор ReentrancyGuard
  • Найруйнівніша вразливість в історії смарт-контрактів — The DAO, 2016

Приклад Reentrancy: код Solidity

// Вразливий код (Vulnerable)
function withdraw() {
    uint amount = balances[msg.sender];
    // 1. Відправка ETH - атакуючий
    //    повторно викликає withdraw()!
    msg.sender.call{value: amount}("");
    // 2. Оновлення балансу - ЗАПІЗНО!
    balances[msg.sender] = 0;
}

// Захищений код (Checks-Effects-Interactions)
function withdraw() {
    uint amount = balances[msg.sender];
    // 1. Check: перевірка
    require(amount > 0, "No funds");
    // 2. Effect: оновлюємо стан ПЕРШИМ
    balances[msg.sender] = 0;
    // 3. Interaction: зовнішній виклик
    msg.sender.call{value: amount}("");
}

Parity Wallet — $30M + $150M заблоковано

  • Липень 2017: публічна функція ініціалізації (initWallet) без захисту доступу (Access Control)
  • Зловмисник викликав initWallet(), оголосив себе власником (owner) та вивів $30 мільйонів
  • Листопад 2017: інший користувач випадково викликав selfdestruct() на бібліотечному контракті
  • Бібліотека знищена — всі залежні гаманці перестали працювати
  • $150 мільйонів ETH заблоковано назавжди — кошти існують, але недоступні
  • Урок: критичні функції потребують модифікаторів onlyOwner та OpenZeppelin AccessControl

Переповнення цілих чисел (Integer Overflow/Underflow)

  • uint256 max + 1 = 0 — переповнення (overflow), обхід перевірки балансу
  • uint256 0 - 1 = 2^256 - 1 — обернене переповнення (underflow), створення токенів "з нічого"
  • До Solidity 0.8 арифметичні операції не мали автоматичних перевірок
  • SafeMath (OpenZeppelin): бібліотека для безпечної арифметики у старих версіях
  • Solidity 0.8+: компілятор автоматично відкидає транзакцію при переповненні
  • Зловмисники використовували overflow для обходу перевірок require(balance >= amount)

Front-Running та MEV

  • Транзакції перед включенням у блок потрапляють у публічний пул очікування (mempool)
  • Атакуючий бачить вигідну pending-транзакцію (наприклад, великий обмін токенів)
  • Відправляє свою транзакцію з вищою ціною газу (gas price) — вона включається першою
  • MEV (Maximal Extractable Value): систематичне витягування прибутку з порядку транзакцій
  • Sandwich-атака: купівля перед жертвою + продаж після — прибуток на різниці цін
  • Flashbots: приватний пул транзакцій для захисту від MEV-ботів

Маніпуляція оракулами (Oracle Manipulation)

  • Смарт-контракти не мають доступу до зовнішніх даних — "бачать" лише стан блокчейну
  • Оракули (Oracles): спеціальні сервіси, що надають ціни активів, курси, дані подій
  • Маніпуляція оракулом = маніпуляція контрактом — хибні дані призводять до хибних дій
  • Flash Loan Attack: миттєва безкоштовна позика для тимчасової маніпуляції ринковою ціною
  • Chainlink: децентралізована мережа оракулів з агрегацією від багатьох джерел
  • TWAP (Time-Weighted Average Price): середньозважена ціна за період — стійкість до маніпуляцій

Інструменти безпеки (Security Tools)

Slither

Статичний аналіз (Static Analysis) — сканує код на 80+ відомих вразливостей без виконання контракту

Mythril

Символічне виконання (Symbolic Execution) — аналіз усіх можливих шляхів виконання коду

Echidna

Фаз-тестування (Fuzzing) — генерує випадкові входи для виявлення порушень інваріантів

Certora

Формальна верифікація (Formal Verification) — математичний доказ коректності за будь-яких входів

Безпечний цикл розробки (Secure Development Lifecycle)

Аудит та тестування (Audit & Testing)

  • Unit-тестування: 100% покриття коду — кожна функція з валідними та невалідними входами
  • Fuzz-тестування (Echidna, Foundry): випадкові вхідні дані для виявлення граничних випадків
  • Статичний аналіз (Slither, Mythril): автоматичне сканування на відомі патерни вразливостей
  • Формальна верифікація (Certora, K Framework): математичний доказ властивостей контракту
  • Незалежний аудит: OpenZeppelin, Trail of Bits, Consensys Diligence — стандарт індустрії
  • Багаторівневий підхід: жоден окремий метод не є достатнім — комбінація усіх рівнів

Програми винагород (Bug Bounty Programs)

  • Immunefi: найбільша платформа Bug Bounty у Web3-просторі
  • Виплати до $10 мільйонів за критичні вразливості у DeFi-протоколах
  • Економічний стимул для "білих хакерів" (White Hat Hackers) повідомляти, а не експлуатувати
  • Постійний розподілений аудит: глобальна спільнота дослідників безпеки
  • Незалежні аудитори: OpenZeppelin, Trail of Bits — обов'язкові перед деплоєм великих контрактів
  • Комбінація Bug Bounty + професійний аудит = найвищий рівень захисту смарт-контрактів
