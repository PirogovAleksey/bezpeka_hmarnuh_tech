Тема 8.3: Аналіз шляхів атаки (Attack Path Analysis)

Що таке шлях атаки?

  • Шлях атаки — послідовність кроків від точки входу до критичного активу
  • Crown Jewels: бази клієнтів, фінансові системи, секрети, IP
  • Privileged Identities: admin-роль, master-ключ KMS, root-акаунт
  • Жодна слабкість окремо не катастрофа — катастрофа в комбінації
  • Мапінг на MITRE ATT&CK Cloud Matrix: Initial Access → Execution → Privilege Escalation → Lateral Movement → Exfiltration

Графовий підхід: модель середовища

Оцінка ризику: експлуатованість × вплив

  • Експлуатованість: публічна точка входу, відомий експлойт (CISA KEV), EPSS, відсутність MFA
  • Вплив: кількість записів, клас даних (PII/PHI/PCI), регуляторика, blast radius
  • Risk Score = Exploitability × Impact, обидва значення нормовані до [0,1]
  • Шляхи > 0,8 — критичні; > 0,6 — високі
  • 73% більше критичних ризиків розв'язує команда з attack path analysis при тих самих ресурсах (Sysdig 2024)

Реальні кейси: де attack path analysis спрацював би

  • MGM Resorts (2023): Identity (Okta soc-eng) → Azure AD admin → vCenter → ESXi mass encryption. CIEM показав би невикористаний admin-доступ.
  • Snowflake / UNC5537 (2024): infostealer credentials → Snowflake без MFA → масовий експорт. CIEM + DSPM повідомили б до інциденту.
  • Toyota Connected (2023): public GitHub repo → AWS access key → S3 → 260 000 записів. Code-to-cloud + secret scanning виявили б витік.
  • Capital One (2019): WAF misconfig → SSRF → IMDSv1 → широка IAM-роль → 100 млн записів. Класичний multi-step attack path.

Ключові висновки

  • Реальні атаки — це ланцюги слабкостей, а не окремі знахідки
  • Графова кореляція показує шляхи, невидимі для класичних інструментів
  • Пріоритезація за Risk Score дає чіткий план дій замість тисяч сповіщень
  • Інтеграція з MITRE ATT&CK Cloud Matrix — стандарт мапінгу шляхів атаки
  • 12 критичних шляхів цінніші за 47 000 ізольованих знахідок Medium
