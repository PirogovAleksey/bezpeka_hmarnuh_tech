Тема 8.2: Архітектура та компоненти CNAPP

Шари CNAPP-платформи

Шість компонентів CNAPP

  • CSPM — конфігурації, бенчмарки CIS/NIST, відповідність регуляторним рамкам
  • CWPP — сканування образів, eBPF runtime-моніторинг, виявлення шкідливого ПЗ
  • CIEM — ефективні права, виявлення надмірних дозволів, шляхи ескалації
  • Container/Kubernetes Security — CVE в образах, KSPM, admission control
  • IaC Security — Terraform, Bicep, Helm — у IDE, pre-commit, PR
  • DSPM — виявлення PII/PCI, потоки даних, статус шифрування

Cloud Asset Graph: чому графова модель

  • Вершини: ресурси, ідентичності, мережі, дані, артефакти розробки
  • Ребра: зв'язки доступу, IAM-права, мережева зв'язність, довірчі відносини
  • Запит без графа: "знайди публічні бакети" — десятки тисяч результатів
  • Запит з графом: "публічні бакети з PII, доступні з compromised pod через надмірну роль" — одиниці
  • Принцип: цінність — у переходах між знахідками, а не у самих знахідках

Кореляція компонентів: матриця збагачення

  • CSPM (публічний бакет) + DSPM (PII): Critical — експозиція 2,1 млн записів
  • CWPP (CVE-2024-21626) + Network (публічний ALB): експлуатовний з інтернету
  • CIEM (iam:PassRole) + Container (compromised pod): шлях до admin
  • IaC (незашифрований EBS) + CSPM (deployed): drift між кодом і runtime
  • DSPM (БД-дублікат у dev) + CIEM (47 розробників): порушення GDPR Art. 5

Ключові висновки

  • CNAPP — не моноліт: чотири шари (збір, граф, аналіз, інтерфейс)
  • Сила платформи — у Cloud Asset Graph, що з'єднує дані всіх компонентів
  • DSPM з 2024 р. — фактичний обов'язковий стовп CNAPP
  • Безагентний підхід покриває 80–90% потреб; агенти eBPF — для глибокого runtime
  • Кореляція двох знахідок дає більше цінності, ніж сотня ізольованих
