Тема 7.1: Проблема помилкових конфігурацій (Cloud Misconfiguration)

Масштаб проблеми

>80%

№1
загроза в рейтингу CSA Top Threats to Cloud Computing 2024
82%
помилок — людський фактор, а не дефект платформи (CSA, 2024)

Таксономія помилкових конфігурацій

  • Ідентичність (IAM): root без MFA, "Action": "*", довготривалі ключі доступу
  • Сховище (Storage): публічний S3-бакет, Azure Blob без автентифікації, без шифрування
  • Мережа (Network): Security Group 0.0.0.0/0:22, default VPC
  • Обчислення (Compute): IMDSv1 замість v2 (CVE-2021-3156), публічні AMI
  • Журналювання: CloudTrail вимкнено, відсутність перевірки цілісності журналів

Знакові інциденти 2023–2025

  • Snowflake / UNC5537 (2024): сотні клієнтських акаунтів, AT&T (73 млн), Ticketmaster (560 млн) — причина: MFA не був обов'язковим
  • Scattered Lapsus$ Hunters (2025): M&S, Co-op, Jaguar Land Rover, клієнти Salesforce — викрадені OAuth-токени, SSO без обмежень за IP
  • Microsoft AI Research (2023): надмірно широкий SAS-токен відкрив 38 ТБ внутрішніх даних
  • Capital One (2019): помилково налаштований WAF + IMDSv1 → SSRF, 100+ млн записів, штраф $80 млн

Чому помилки системні?

  • Складність платформ: AWS — 200+ сервісів, десятки параметрів у кожному
  • Швидкість DevOps: розгортання без перевірки безпеки (security review)
  • IaC: інфраструктура як код масштабує і хороші практики, і помилки
  • Модель спільної відповідальності: конфігурація — завжди на стороні клієнта

Ключові висновки

  • Помилкові конфігурації — причина №1 хмарних інцидентів (Verizon DBIR 2025, CSA 2024)
  • Ручні аудити та власні скрипти не масштабуються — потрібна автоматизація
  • Інциденти 2024–2025 підтверджують: проблема не зникає, а посилюється через SaaS та IAM-помилки
  • CSPM — спеціалізована категорія інструментів для безперервного виявлення таких помилок
