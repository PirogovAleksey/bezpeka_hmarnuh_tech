Тема 7.4: Інструменти, практика та еволюція до CNAPP

Ландшафт інструментів

Ключові платформи ринку

  • Нативні: AWS Security Hub, Microsoft Defender for Cloud, GCP Security Command Center
  • Wiz: безагентна, граф залежностей, аналіз шляхів атаки — оцінка компанії > $10 млрд
  • Palo Alto Prisma Cloud: лідер Gartner Magic Quadrant, CSPM + CWPP + CIEM + DSPM
  • Orca Security: SideScanning через знімки дисків
  • Open Source: Prowler (CLI + CIS), Steampipe (SQL), Checkov (IaC)

Стратегія впровадження

1
Оцінка (1–2 тижні)
2
Пілот (2–4 тижні)
3
Розгортання (4–8 тижнів)
4
Оптимізація (постійна)

Найкращі практики (Best Practices)

  • Видимість насамперед: інвентаризація до примусу політик
  • Пріоритезація: критичні + публічна експозиція + продакшн + регульовані дані
  • Співпраця з DevOps: самообслуговування, чіткі інструкції з усунення
  • Обережна автоматизація: низькоризикові дії — автоматично, IAM/мережа — ручне підтвердження
  • Метрики: MTTD, MTTR, динаміка оцінки відповідності

Еволюція CSPM → CNAPP

  • CNAPP — платформа захисту хмарних застосунків = CSPM + CWPP + CIEM + DSPM
  • Корельовані знахідки: помилкова конфігурація + вразливість + надмірні права = шлях атаки
  • Єдина панель (single pane of glass) для всієї хмарної безпеки
  • Прогноз Gartner: до 2029 року 40% enterprise-впроваджень Zero Trust у хмарі спиратимуться на CNAPP

Ключові висновки

  • Помилкові конфігурації — причина №1 хмарних інцидентів (>80%, Verizon DBIR 2025)
  • CSPM автоматизує виявлення, пріоритезацію та усунення на масштабі
  • Стратегія вибору: починати з нативних, розширювати сторонніми або open source
  • Інтеграція з DevOps та CI/CD — критична умова успіху CSPM-програми
  • Майбутнє — конвергенція з CWPP/CIEM/DSPM у єдину CNAPP-платформу
