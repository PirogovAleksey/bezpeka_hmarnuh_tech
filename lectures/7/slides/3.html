Тема 7.3: Архітектура та інтеграція CSPM

Компоненти CSPM

Шар збору та політик

  • Інтеграція через API: AWS, Azure, GCP — доступ лише для читання (read-only)
  • Оновлення за подіями: CloudTrail, Azure Activity Log — у реальному часі
  • Безагентний режим: розгортання за хвилини, без інсталяції агентів
  • Рушій політик: бібліотеки CIS/NIST + власні правила на OPA/Rego
  • Політика як код (policy-as-code): однакові правила для runtime та IaC-сканування

Моделі розгортання

SaaS

Швидкий старт, автоматичні оновлення, вендор зберігає метадані

Self-hosted

Повний контроль над даними (Prowler, CloudSploit)

Гібридна

Дані локально, керування у SaaS

CI/CD-інтеграція (Shift-Left)

  • Сканування IaC до розгортання: Terraform, CloudFormation, Bicep, Pulumi
  • Інструменти: Checkov, tfsec, Terrascan, KICS, Trivy-config
  • Pre-commit-хуки для розробників — виявлення проблем ще в IDE
  • PR-перевірки: блокування помилкових конфігурацій до merge
  • SARIF-формат для відображення у GitHub Security

Інтеграція з SIEM, SOAR та тикетингом

  • SIEM: пересилання знахідок у Splunk, Microsoft Sentinel, Elastic
  • SOAR: запуск плейбуків для авторемедіації
  • Тикетинг: автоматичне створення тикетів у Jira, ServiceNow + SLA-трекінг
  • Сповіщення: Slack, Microsoft Teams, PagerDuty для критичних знахідок

Ключові висновки

  • Архітектура CSPM — п'ять шарів: збір, нормалізація, політики, аналіз ризиків, представлення
  • Безагентний підхід став стандартом — швидкість розгортання важливіша за глибину runtime
  • Політика як код забезпечує єдиний набір правил для runtime та pre-deployment
  • CSPM не існує окремо — його цінність розкривається через інтеграції з SIEM, SOAR, CI/CD
